# 写作：推进节拍（writing-beats）

<what-to-do>

用户已经（或将）传来一份原始素材的 markdown 文件。这是**开采（exploit）**：探索已经做完，料堆已经定型。选定一条穿过它的路径，然后开采料堆去填每一拍。

如果用户没说文章存到哪里，问一次，并记住路径。

然后跑一段逐拍的旅程，像「自选冒险」那样：

1. **确立前提（prerequisites）。** 在任何节拍之前，与用户敲定读者走进来时已经知道什么：那些从一开始就**已落地（grounded）** 的概念。其余一切都必须由某一拍先落地，后面的拍才能用它。见[落地](#落地)。
2. 从原始素材里写出 2~3 个候选**起手拍（starting beat）**。每个都是进入文章的不同入口。每一拍只能依靠已落地的概念；并注明它落地了哪些新概念。写进文章文件之前先给用户看这些节拍，由用户挑一个。顺便预告这个选择解锁了哪些节拍，就像让用户看见前方一小段路。
3. 用户选定起手拍后，**只把那一拍**写进文章文件。一拍可以是一句话，也可以是几段，顺它自然的大小。然后停下。
4. 从磁盘重读文章文件。然后给出 2~3 个候选**下一拍（next beat）**：从文章现在所站之处，旅程可以转向的不同方向。每一个都必须能从当前已落地集合抵达；并注明各自落地了什么。
5. 循环步骤 3~5，直到文章到达自然的终点。

</what-to-do>

## 落地（Grounding）

每个**概念（concept）**在某一拍依靠它之前都必须**落地**：读者要么带着它走进来，要么在更早的某一拍里遇到过它。一拍若伸手去够未落地的概念，就会丢掉读者 —— 这是这段旅程唯一不能走的动作。单位是概念，不是它的词：一拍可以依靠一个读者没有的想法，哪怕文中毫无术语。当概念有名字（一个**术语 term**）时，落地它意味着把想法和术语一起递到读者手里。

概念落地有两条路：

- **前提（Prerequisite）**：在第一拍之前已落地。观众自带。开头就定死。
- **引入（Introduced）**：某一拍把它建立起来，此后它对每一拍都算落地。

所以每一拍干两件事：它**需要**已经落地的概念，并**落地**新概念。维护一份「目前已落地」的清单，每拍落定就更新它。

这就塑造了「自选冒险」的结构。一个候选拍只有在它需要的一切都已落地时才可抵达；选一个落地了概念 X 的拍，就解锁所有在等 X 的拍。你给下一拍时，它们都必须能从当前已落地集合抵达，并说明各自落地什么，这样用户能看见它打开了哪条路。

最大的杠杆（leverage）是：什么做成前提、什么在文中落地。前提要求太多，就把没有这些背景的读者挡在门外；文中落地太多，开头的拍就淹在定义里。确立前提时与用户敲定这个平衡；每当一个诱人的拍被发现需要一个尚未落地的概念，就重访这个平衡：解法要么是它之前加一个落地拍，要么把该概念提升为前提。

## 什么是一拍

一拍是旅程里的一个动作。它只做一件事：铺一个场景、落一个观点、问一个问题、插一句旁白、拧一下角度。然后停下，把读者留在下一拍可以转向的位置。

一拍的大小由它需要什么决定：

- 如果这个动作就这么多，一句话足够（「然后三周什么都没发生。」）。
- 如果这个动作需要铺垫，一个短段落。
- 如果这一拍是自成一体的场景、论证或例子，几段。

如果一个「拍」需要五段和三个小标题，它就不是一拍，而是两拍粘在一起。拆开。

## 从料堆里取料

从原始料堆里取材料来填充每一拍。你可以改写、拆开、重组或引用。料堆是采石场。

## 结束旅程

文章在旅程走完时结束，不是料堆清空时结束。大多数料堆都会剩下没进去的碎片。这没关系；本来就该准备比所需更多的素材。

## 写作节奏

- 一次只追加一拍。绝不预先写。
- 每次写之前都从磁盘重读文章文件。绝对保留用户的编辑。
- 如果用户大幅改动前面某一拍，让它改变后面写什么。
- 如果用户说「重写那一拍」或「回去试试另一个第 3 拍」，就照做：就地编辑，其余不动。
