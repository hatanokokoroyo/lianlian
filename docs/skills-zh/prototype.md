# 原型（Prototype）

原型是**回答一个问题的用后即弃代码**。问题的性质决定它的形状。

## 选一条分支

确认要回答的是哪个问题 —— 依据用户的提示、周边代码，或者用户在场时直接问：

- **「这段逻辑 / 这个状态（state）模型感觉对吗？」** → [LOGIC.md](../../.agents/skills/prototype/LOGIC.md)。做一个单文件的 HTML（自由操作按钮 + 分页的引导式走查），把状态机（state machine）推过那些在纸面上难以推理的情形，并让非开发者也能操作。
- **「它该长什么样？」** → [UI.md](../../.agents/skills/prototype/UI.md)。在同一条路由上生成若干风格迥异的 UI 变体，用 URL 查询参数 + 悬浮底栏切换。

两条分支产出的东西差别极大，选错就白做整个原型。若问题确实含糊且联系不到用户，就按周边代码来选（后端模块（module） → 逻辑；页面或组件 → UI），并在原型顶部写明这个假设。

## 两条分支都适用的规则

1. **从第一天起就是用后即弃，并且明确标注。** 把原型代码放在它实际会被使用的位置附近（就在它所原型化的模块或页面旁边），让上下文显而易见，但命名要让随手翻到的人能看出这是原型而非生产代码。用于一次性 UI 的路由，遵守项目既有的路由约定；不要发明新的顶层结构。
2. **运行要极其简单。** UI 原型用项目任务运行器的一条命令就能起来：`pnpm <name>`、`python <path>`、`bun <path>` 等。逻辑演示就是一个双击即开的 HTML 文件。无论哪种，启动都不需要动脑。
3. **默认不持久化。** 状态放在内存里。持久化是原型**要检查**的东西，不是它该依赖的东西。若问题明确涉及数据库，就用一个临时库或本地文件，并起一个明显的「PROTOTYPE，可以随便删」的名字。
4. **跳过打磨。** 没有测试，除让原型**能跑**所必需之外没有错误处理，没有抽象。目的是快速学到东西。
5. **把状态露出来。** 每个动作之后（逻辑分支），或每次切换变体时（UI 分支），打印或渲染完整的相关状态，让用户看见什么变了。
6. **做完要留存。** 把验证过的决策折进真正的代码，然后把原型本身作为**一手来源（primary source）**留存：提交到一个从 main 切出的一次性分支，并在实现侧 issue 上留一个指向该分支的上下文指针。答案也要留下（结论，以及它了结的那个问题）—— 写进 issue 或提交。main 只保留被验证的决策。
