# 向导（Wizard）

**向导（wizard）** 是一个 bash 脚本，一步步带一个真人走完一段手工流程 —— 手工做很枯燥，向 AI 重新解释也很枯燥。它逐个打开网址、说清点哪里复制什么、捕获取值、写到该去的地方（`.env`、GitHub secrets），每个阶段都确认，并显示还剩几个阶段。它可能配置第三方服务、跑一次性迁移，或把项目从一个状态（state）搬到另一个状态。

令人愉快的 UX 已经由 [template.sh](../../.agents/skills/wizard/template.sh) 解决：分阶段进度、确认门、跨平台打开 URL（含 WSL）、隐藏输入 secret、幂等的 `.env` upsert、`gh secret`／`gh variable` 写入，以及收尾总结。**你的活只是划定流程范围并编写它的各个阶段。** `STAGES` 标记以上的库在每个向导里都一模一样；这份一致性正是要点：**永远不要手工改它**。

向导默认是临时的：为一次运行而建，存到临时位置或 `scripts/`，做完就删。只有当用户希望仓库里有一条可重复使用的安装路径时才提交它。

## 过程

### 1. 划定流程范围

把真人必须做的每个手工步骤、以及沿途捕获的每个值都理出来。先读仓库，不要凭空问：

- 安装类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、`.github/workflows/*`（每一处 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 迁移或切换类：当前状态、目标状态，以及两者之间的不可逆动作。

然后把有序的阶段清单与每阶段产出的值给用户看并确认：他可以增、删、调序。

**完成判据：** 每个阶段都按顺序命名，并且对每个捕获的值你知道 (a) 人从哪里拿到它，(b) 它写到哪里（`.env`、某个 GitHub secret、两者、或都不写 —— 有些阶段是纯动作），(c) 它是 secret（隐藏输入）还是公开的。

### 2. 画出每个阶段的旅程

对每个阶段，写出真人要走的精确路径：打开哪个 URL、在那里做什么、值显示在哪、填哪个变量 —— 例如「Dashboard → Developers → API keys → Reveal test key → copy」。当你并不真正知道当前的 UI 或确切命令时，就明说，然后问用户或查文档：**绝不**编造可能不存在的步骤。

**完成判据：** 每个阶段都能追溯到一段陌生人也能照做的具体指令。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用每个步骤一个 `stage` 替换示例阶段，按依赖顺序排。使用库里的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为你写的阶段数。

守住模板设定的标准：在索取某个值之前先打开它的 URL；任何 secret 都用 `ask_secret`；每个要留存的值都过 `write_env`；只有 CI 真正需要的值才 `set_secret`；任何不可逆动作之前先 `confirm`。每个 `stage` 都会清屏，只让当前步骤可见：一个阶段只做一件专注的事，别让人需要的东西滚出屏幕。不要动标记以上的库。

### 4. 验证与交付

- `bash -n <script>`；有 `shellcheck` 就跑一遍。
- `chmod +x <script>`。
- **不要**自己端到端跑它：它会开浏览器并阻塞（blocked）在人工输入上。改为静态地追一遍：第 1 步列出的每个值都被捕获，并落到第 1 步说的位置；每个 `set_secret` 的名字与 CI 里的某处 `secrets.*` 引用完全一致。
- 告诉用户怎么跑。若它是可重复的安装路径，就提交它，并从 README 链接过去，让下一个人跑脚本而不是去问 AI。
