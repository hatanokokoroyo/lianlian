# To Tickets

把一份计划、spec 或对话拆成一组**工单（ticket）**：tracer-bullet 垂直切片（vertical slice），每个都声明**阻塞（blocked）**它的那些工单。

issue tracker 与 triage 标签词表（glossary）本应已经提供给你。若没有，说明配置缺失 —— 去读本仓库的 `AGENTS.md` 与 `docs/agents/issue-tracker.md`（`/setup-matt-pocock-skills` 已卸载，不要引导用户运行它）。

## 过程

### 1. 汇总上下文

以对话上下文里已有的东西为出发点。如果用户以参数形式传了一个引用（spec 路径、issue 编号或 URL），取回它并读完正文与评论。

### 2. 探索代码库（可选）

若还没探索过代码库，先探索以了解代码现状。工单标题与描述应使用项目的领域词表，并遵守你所触及区域的 ADR。

寻找**预重构（prefactor）**的机会，让实现更容易："先让改动变简单，再做这个简单的改动。"

### 3. 草拟垂直切片（slice）

把工作拆成 **tracer bullet** 工单。

<vertical-slice-rules>

- 每个切片都穿过每一层（schema、API、UI、测试），切出一条窄但**完整**的路径：是垂直的，**不是**某一层的水平切片（horizontal slicing）
- 一个完成的切片自身可演示、可验证
- 每个切片的大小要能装进一个全新的上下文窗口（context window）
- 任何预重构都应最先做

</vertical-slice-rules>

给每个工单标上它的**阻塞边（blocking edge）**：在它开工前必须完成的那些工单。没有阻塞者（blocker）的工单可以立刻开工。

**大范围重构（wide refactor）是垂直切片的例外。** 所谓大范围重构，是一次机械性改动（重命名一列、改一个共享符号的类型），其**爆炸半径**在整个代码库铺开，一次编辑会同时打断成千上万个调用点，任何垂直切片都无法以绿灯落地。不要硬塞进 tracer bullet，而是按**expand–contract（先扩张后收缩）**排序：先扩张，把新形态加在旧形态旁边，什么都不坏；然后按爆炸半径分批（按包、按目录）迁移调用点，每批一个工单、被扩张工单阻塞，因为旧形态还在，CI 可以一批批保持绿灯；最后收缩，在没有调用者剩下时删掉旧形态，这个工单被所有迁移批次阻塞。若连各批次都无法单独保持绿灯，就保留该顺序，但让它们共享一个集成分支（integration branch），且全部阻塞一个最终的「集成并验证」工单 —— 绿灯只在那里承诺。

### 4. 盘问用户

把提议的拆分以编号清单呈现。每个工单显示：

- **标题**：简短的描述性名称
- **阻塞于（Blocked by）**：必须先完成的那些工单（若有）
- **交付什么**：这个工单让哪个端到端行为成立

问用户：

- 粒度感觉对吗？（太粗 / 太细）
- 阻塞边正确吗：每个工单是否只依赖真正卡住它的工单？
- 是否有工单该合并或进一步拆分？

反复迭代，直到用户批准这份拆分。

### 5. 把工单发布到已配置的 tracker

发布已批准的工单。**怎么发**取决于 `/setup-matt-pocock-skills`（本仓库已完成，见 `docs/agents/issue-tracker.md`）配置的 tracker；两种情况下工单内容一样，只有阻塞边的形态不同：

- **本地文件** → 按依赖顺序（阻塞者在前）写到 `.scratch/<feature-slug>/issues/<NN>-<slug>.md`，从 `01` 起编号。每个文件的 "Blocked by" 列出它依赖的编号/标题。使用下面的单工单文件模板：一个文件一个工单，**绝不**用单个合并文件。
- **真实 issue tracker（GitHub、Linear……）** → 按依赖顺序（阻塞者在前）每工单一个 issue，这样每个工单的阻塞边才能引用真实标识。平台有原生阻塞关系就用它；否则把每个工单的 "Blocked by" 设为阻塞它的 issue。若来源是一条既有 issue，把每个工单做成它的子 issue（见 tracker 文档中的对应操作）。除另有指示，打上 `ready-for-agent` triage 标签，因为这些工单按构造就是 agent 可抓的。

按**前沿（frontier）**推进：任何阻塞者都已完成的工单。纯线性链条就是从下往上。

**不要**关闭或修改任何父 issue。

两种形态都避免写具体文件路径或代码片段：它们过期很快。例外：若原型产出的片段比散文更精确地编码了某个决策（状态机（state machine）、reducer、schema、类型形状），就内联它并简短注明来自原型。只保留决策密集的部分，不要可运行的 demo，只要关键片段。
