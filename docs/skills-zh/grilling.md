# grilling

把用户访谈到不留情面，直到达成共识。把这画成一棵**设计树（design tree）**：每个决策都会分出挂在它下面的决策。

按**轮次**推进这棵树。**前沿（frontier）** 是那些前提已经落定的决策：你现在就能问、不必猜测尚未听到的答案的问题。一轮里把整个前沿都问掉：给每个问题编号，并给出你推荐的答案。然后等用户回答，再进下一轮。

一轮的格式如下：

```
❓ **Q1** - **<问题标题>**：<问题正文，可能多段，含多个选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可能多段，含多个选项>

➡️ <你推荐的答案>
```

把每个问题措辞成「用户回答『是』就等于采纳你的推荐答案」。

每一轮用户的回答都会重塑这棵树：已定的决策把前沿往外推，解锁那些依赖它们的问题。重新计算前沿，问下一轮。如果某个问题的答案依赖于本轮中仍然悬空的问题，它属于*更晚*的轮次，不是本轮。

找**事实**是你的活，永远不是用户的活。当前沿问题需要来自环境的事实（文件系统、工具等）时，派一个带全新上下文窗口（context window）的 subagent 去找；不要问用户任何你自己能查的东西。不要为此阻塞（blocked）：正在跑的探查属于未落定的前提，只有它下游的问题等这个 subagent 报告，前沿其余部分现在就问。**决策**是用户的：逐条摆给他，然后等。

当**前沿为空**时会话结束：设计树的每个分支都走到了，没有东西被悄悄假设。在用户确认你们已达成共识之前，不要据此动手。
