# 写给 agent 的文档（writing-for-agents）

写任何「被 agent 消费的文档」的参考：一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份被指针指向的文档。打包形式不同，写法不变：同一套杠杆（leverage）让每一份都变得**可预测**，因为 agent 每次都走同样的*过程*，而不是产出同样的结果。

当你写的是 skill 时，读 [`SKILL-MECHANICS.md`](../../.agents/skills/writing-for-agents/SKILL-MECHANICS.md) 了解 frontmatter、调用方式的选择，以及路由型 skill。

## 上下文指针（context pointer）

**上下文指针**是存在 agent 上下文里的一个引用，它点名某份上下文之外的材料，并编码了「什么条件下该去取它」。skill 的 description 是一个指针；`AGENTS.md` 里点名某份文档的一行是同一个东西。决定 agent 何时去取、以及取得有多可靠的，是**指针的措辞**，不是它的目标。把一个必备目标放在措辞孱弱的指针后面，是一个**方差 bug**：先磨利措辞，只有磨不动时才把材料内联。

指针干两件事：说明材料是什么，并列出该触发去取它的**分支**（分支 = 这份文档处理的一个独立情形，因此不同的运行会走不同路径）。每个常驻指针的每个字都在**每一轮**付费，所以它比正文更需要狠剪：

- **把领词（leading word）前置**：指针的字就是它触发力的所在。
- **一个分支一个触发。** 给同一个分支换名字的同义词，是同一个分支写了两遍；合并它们，只留真正不同的分支。
- **砍掉正文已经承载的身份信息。**

## 两种负载

你添加的每份文档与指针，都在花掉两种预算之一：

- **上下文负载（context load）** 是常驻材料占 agent 窗口的成本：一行 `AGENTS.md`、一个 skill description、任何每一轮都在上下文里的东西 —— 无论是否触发，都在花 token 与注意力。
- **认知负载（cognitive load）** 是落在人身上的成本：有哪些文档存在、什么时候该取哪一份。人就是索引。**这不是要最小化的成本**：它是人的能动性的价格；在人判断重要的地方花它，在不重要的地方去掉它。

只通过指针到达的材料，以指针自己那一行为代价，逃掉了上下文负载；完全没有指针的材料，则整个骑在认知负载上。

## 信息层级（information hierarchy）

一份文档由两类内容构成：**步骤**（agent 依序执行的动作）与**参考**（按需查阅的定义、规则、事实）。两者自由混合：全是步骤（一份配方）、全是参考（一份评审的规则、本技能），或两者兼有。核心决策是每一块材料坐在**信息层级**的哪一级 —— 一架按「agent 多急需这份材料」排序的梯子：

1. **文件内步骤**是主层：agent 按顺序做什么。
2. **文件内参考**按需查阅。常常是一个合法的扁平同级集合（一份评审的每条规则在同一级），这种安排没问题，不是坏味道（code smell）。
3. **披露的参考（disclosed reference）** 被推到独立文件里，由上下文指针抵达，只在指针触发时加载。范围从同目录的兄弟文件，一直到任意位置的外部参考 —— 任何文档都能指向它。

往下推得太少，顶层就臃肿；推得太多，就把 agent 真正需要的材料藏起来。这个张力就是全部决策。

**渐进披露（progressive disclosure）** 就是沿梯子下移（移出主文件、放到指针后面），让顶层保持可读。它主要不是 token 优化：它是保护这套层级的方式。分支是最干净的披露判据：**每个分支都需要的内联，只有部分分支会取到的推到指针后面**。当文档里有步骤时，本该被披露的文件内参考会把这些步骤埋掉，让「注意到它们」变成掷硬币：这不只是可读性的杠杆，也是方差的杠杆。

**就近安置（co-location）** 是文件内的伙伴：梯子决定一块材料坐在*多下面*，就近安置决定它到了那里之后*身边坐着什么*。把一个概念的定义、规则和注意事项放在同一个标题下而不是散开，这样读到一处就把邻居一起带来。判据：这份文档应当读起来像「为 agent 写的文档」。分组好的材料读起来是这样；散落的不是。（与重复不同：重复是把一个含义写在两处；散落是把一个含义碎在多处。）

**漫延（sprawl）** 是这里的失败模式：文档就是太长了，即使每行都还有效且唯一。注意力在超额部分被摊薄，而每多一行就多一行要维持相关性。解药就是梯子：把参考披露到指针后面，并按分支或时序切开，让每条路径只携带它需要的东西。

## 步骤与完成判据

每个步骤都以一个**完成判据（completion criterion）** 收尾，即告诉 agent「这件事做完了」的条件。两个属性让它成为杠杆：

- **清晰度（clarity）**：agent 能分辨「做完」与「没做完」吗？模糊的边界（「达成理解」）会招来**过早完成（premature completion）**：在真正做完之前就结束这一步，注意力滑向*「已经做完了」*。眼前仍可见的后续步骤（**完成后步骤，post-completion steps**）提供这股拉力；判据的清晰度是阻力。按顺序防守：**先磨利边界**（局部且便宜）；只有当它确实无法更精确、*且*你观察到了那股急躁时，才通过拆开序列把后续步骤藏起来。隐藏只有在跨真实上下文边界时才有效（一次交接、或一次 subagent 派发；内联调用会把后续步骤留在上下文里，什么都没清掉）。
- **要求（demand）**：它要求多少。「每个被改动的模型都交代到」强迫做透，而「产出一份改动清单」不会。要求驱动**推敲（legwork）** —— agent 在工作内部所做的挖掘，它潜伏在措辞里，而不是写成独立的一步；而且它不受步骤约束：「每条规则都应用了」约束一组扁平参考，正如「每一步都做完了」约束一个序列 —— 这就是一份全参考文档也能携带完备性标准的方式。

最强的判据既**可核查**又**穷尽**。

## 何时拆分

把一份文档拆成两份会花掉两种负载之一，所以只在切口值这个价时才拆：

- **按序列拆**：当后续步骤会引诱 agent 赶眼前这一步时，把这段步骤切开。让它们看不见会驱动当前任务上更多的推敲。小心反方向：合并序列会把每一步的后续步骤暴露给下一步，招来过早完成。
- **按调用方式拆**，skill 专属：见 [`SKILL-MECHANICS.md`](../../.agents/skills/writing-for-agents/SKILL-MECHANICS.md)。

## 领词（leading words）

**领词**是模型预训练里已经存在的一个紧凑概念，agent 在运行文档时用它来思考（*lesson*、*fog of war*、*tracer bullets*）。它作为一个 token 被反复使用，而不是一句话，于是积累出一份分布式定义，并用最少的 token 锚住一大片行为 —— 靠的是征用模型已有的先验。自造词也行，只要你把它定义清楚；但自造词不征用任何先验：你用定义所需的 token 付出代价，而预训练里的词免费给你。所以先用已有的词。

它在两处锚定。在正文里锚**执行**：词一出现，agent 每次都去够同一个行为；在扁平参考里，它把注意力集中在某一类要找的东西上。在指针里锚**调用**：当同一个词出现在你的 prompt、你的文档、你的代码库里，agent 会把这份共享语言和那份材料连起来，更可靠地去取它。

主动寻找用领词重构的机会。三处各写一遍的三元组、一个花了一句话去比划某个想法的指针。每一处都是求着塌缩成单个 token 的段落：

- 「快、确定、开销低」→ _tight_（一个 *tight* 的循环）。
- 「一个你相信的循环」→ _red_，把模糊的门变成二值可观察状态（循环在这个 bug 上变*红*，否则不）。

你赢两次：更少的 token，以及一个更锋利的钩子供 agent 挂住思考。可以假定每份文档都带着一些能被领词退休掉的重述。去找它们。

**否定（negation）** 是这条杠杆旁边的失败模式：靠禁令来引导，会把被禁行为拖进上下文，让它更可得而非更不可得。*别想大象*，结果满脑子都是大象；否定是个弱修饰语，会被高度激活的概念盖过去，于是那条禁令有一半读起来像「去做这件事」的指令。要提示**正面**：说出目标行为（「写一行注释」），被禁的那个就从未被说出口。禁令只有在它是你无法用正面措辞表达的硬护栏时才配得上位置；即便如此，也要配上正面目标，让注意力落在该做什么上。

## 修剪（Pruning）

- 让每个含义只有一个**单一事实源**：一处权威位置，于是改行为就是改一处。**重复**（同一含义出现在不止一处）花维护成本与 token，还会把一个含义在梯子上的显著度抬高到超过它真实的层级。（它是领词的无意反面 —— 领词有意重复一个 token，绝不重复含义。）
- **环境**也是一个事实源（`package.json` 的 scripts、配置文件、目录布局、`--help` 输出），复述它的文档是一份**缓存**：一次查找的副本，只有当那次查找很贵时才配得上它的负载。缓存那些 agent 靠看是找不到的：没写下来的约定、选择背后的原因、没有配置文件会承认的坑。把「一个文件、一条命令就能查到」的东西留给环境，它们在那儿不会过期。
- 逐行检查**相关性**：它还和这份文档要做的事有关吗？一行会因「从不与任务相关」（纯说明，或本该被披露的分支）失去相关性，也会因它所描述的行为或世界变化而过期。更短的文档更容易保持相关。没有修剪纪律，默认命运是**沉积（sediment）**：过期的层一层层落下 —— 因为添加感觉安全、删减感觉危险 —— 直到你必须钻透它们才能找到还有效的部分。
- 逐句搜**空转（no-ops）**：模型默认就会遵守的指令，花了负载却什么都没说。判据（它相对默认行为改变了行为吗？）是相对于**模型**的，不是相对读者的：两个人对某句是不是空转有分歧，其实是他们对默认行为有分歧，靠**跑这份文档**而不是辩论来定。一句话不合格时，删掉整句，而不是从里面抠字。同一判据也用来给领词打分：太弱、赢不过默认的词（agent 本来就相当彻底时，你说「要彻底」）就是空转，修法是换一个更强的词（_relentless_），而不是换一种技术。
