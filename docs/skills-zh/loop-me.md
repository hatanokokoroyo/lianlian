# 帮我盘循环（loop-me）

跑一场有状态（state）的 `/grilling` 会话，唯一产出是**工作流（workflow）** spec。使用拷打（grilling）的纪律（不留情面、一次一轮问题、每问附带推荐答案），对准下面的词汇与目标。随着拷打把问题敲定，创建、编辑、删除 spec。

## 循环视角（the loop lens）

**循环（loop）** 是用户生活里反复出现的模式：他的职业、他的一周、他的早晨、某一项重复的活动。把生活想象成循环套循环，能揭示这些活动其实有多可预测 —— 而可预测正是它们值得**委派**的原因。用这个视角找出值得写 spec 的循环，并主动提出用户自己没注意到的那些。

**工作流（workflow）** 是一个循环的 spec，落到实处。你在一个循环上跑工作流：循环是它运行时的实例化。工作流住在 `workflows/*.md`，它们是事实源。

## 词汇

一套共享语言，只在某个工作流需要时才取用：绝不是清单。**不要强加任何结构性要求**：除非拷打表明需要，工作流不需要 AI、不需要检查点、不需要排程。

- **触发器（Trigger）**：每次运行由什么引发 —— 一个**事件**（新邮件、新 issue）或一个**排程**（每天早上）。事件触发通常更高效。
- **检查点（Checkpoint）**：一个人在环里的点，请用户核实或决策。有些工作流一个都没有、全自动跑；有些根本不用 AI。
- **右推（Push right）**：把检查点尽量往后推。在牵涉人之前做掉最大量的工作，于是人只在很晚的时候被问一次，而且一切都已备好。
- **简报（Brief）**：检查点呈现的东西 —— 一份紧实、可直接决策的摘要（产出了什么、为什么、以及指向资产本身的链接），绝不是原始输出。用户读的是简报（brief），不是草稿。评审速度是硬要求。

## 完成判据

一个工作流 spec 的完成判据是：一个实现 agent 能不问任何一个问题就把它建出来。在那之前继续拷打；还剩一个问题就都算没做完。

## 工作区

- `workflows/*.md`：一个工作流一份 spec。
- `NOTES.md`：关于用户世界的原始笔记 —— 他用什么工具、处理哪些渠道、以及他自己对这两者的叫法。当它为空或很薄时，先访谈他的世界，再谈任何 spec。术语模糊时就磨成 canonical 说法，并记在这里。
