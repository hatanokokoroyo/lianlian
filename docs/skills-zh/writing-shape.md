# 写作：塑形（writing-shape）

<what-to-do>

用户已经（或将）传来一份原始素材的 markdown 文件。把它当成输入的料堆：可能是整齐的碎片清单，也可能是一整墙无结构的散文，或一份会话记录。格式不重要。做任何事之前先从头到尾读一遍。

然后跑一场塑形会话，产出一份**独立的**文章文档。这是**开采（exploit）**：探索已经做完，料堆已经定型 —— 选定结构，开采料堆去填它。**不要编辑原始素材文件**：对本技能它是只读的。

如果用户没说文章存到哪里，问一次并记住路径。

</what-to-do>

<supporting-info>

## 循环

1. **读料堆。** 完整读输入文件。形成对里面有什么的感觉。
2. **确立前提。** 与用户敲定读者走进来时知道什么：那些从一开始就**已落地（grounded）** 的概念。其余一切都必须由某个块先落地，后面的块才能依靠它。见[落地](#落地)。
3. **起草 2~3 个候选开头。** 每个开头都应暗示不同的论点或角度。全都摆出来。逼用户挑一个或拼一个混合体。选定的开头决定了文章其余部分必须做什么。
4. **一段一段地长。** 开头落定后，问「有了这个开头，读者接下来需要听到什么？」从料堆里取材料来回答。下一块只能依靠已落地的概念，并在落地时引入新概念。就下一块的形式与用户争论：段落、列表、表格、提示框、引语、代码块。每个格式选择都应当是有意为之且说得通的。
5. **边写边追加到文章文件。** 不要攒批。每个商定的段落或块立刻写进去，让用户看见文章逐渐成形。
6. **循环第 4 步直到文章完成。** 由用户决定何时完成。

## 落地

每个**概念**在某个块依靠它之前都必须**落地**：读者要么带着它走进来，要么在更早的块里遇到过它。一个块若去够未落地的概念，就会丢掉读者。单位是概念，不是它的词：一个块可以依靠读者没有的想法，哪怕文中毫无术语。当概念有名字（一个**术语**）时，落地它意味着把想法和术语一起递到读者手里。

概念落地有两条路：

- **前提**：在开头之前已落地。读者自带。开头就定死。
- **引入**：某个块把它建立起来，此后它对文章余下部分都算落地。

维护一份「目前已落地」的清单。当你问「读者接下来需要听到什么？」时，下一步所需的某个未落地概念本身就是答案：先落地它（在这里或在更早的块里），否则这一步走不了。这是[从料堆里取料](#从料堆里取料)往上抬一个层级的「点出缺口」：那里是料堆缺材料，这里是文章缺地基。

杠杆（leverage）在于：什么做成前提，什么在文章里落地。前提要求太多会把读者挡在外面；文章里落地太多，开头会淹在定义里。确立前提时与用户敲定它。

## 对话感

这是一场反向的拷打（grilling）会话。在立意阶段，问题是「你究竟注意到了什么？」这里的问题是「这篇文章究竟在论证什么，读者需要按什么顺序听到它？」要顶回去。不让孱弱的过渡蒙混过去。如果一段挣不到自己的位置，就砍掉。

要持续使用的具体问法：

- 「这一段为读者做的事，是上一段没做的什么？」
- 「如果我把这段删了，什么会坏？」
- 「这是散文，还是该做成列表？为什么是散文？」
- 「这句话在干两件事：拆开，或挑一件。」
- 「开头承诺了 X，我们漂到了 Y。要么把线重新牵回去，要么改开头。」

## 从料堆里取料

把原始素材当采石场，不是剧本。取一片碎片，按周边段落改造它，放进去。一片碎片可以被拆到多段、与另一片合并、或被改写。料堆的职责是被开采；文章的职责是读起来像一个声音。

如果料堆缺了文章需要的东西，明确点出缺口：「这里需要一个例子，料堆里没有。现在给我一个，否则我们砍掉这一节。」

## 该真的争论的格式选择

选择怎么呈现一个块时，把这些取舍**说出来**与用户权衡，而不是默选：

- **散文 vs 列表。** 散文承载论证；列表承载并列项。若各项并不真正并列，散文更好；若确实并列，列表扫读更快。
- **内联 vs 提示框。** 提示、警告、旁白放进提示框（`> [!TIP]`、`> [!NOTE]`），但仅当它们内联时真的会带偏主论证；否则留在内联。
- **表格 vs 重复结构。** 同样的形状同样字段重复 3 次以上 → 表格；否则用散文加粗体引导词。
- **引用 vs 改写。** 原文措辞本身就是要点 → 引用；只有想法重要 → 改写。
- **代码块 vs 内联代码。** 多行、可运行、或作说明用 → 代码块；单个 token 或标识符 → 内联。

## 写作节奏

每块商定后就追加到文章文件。每次写之前从磁盘重读文件：用户可能在你两轮之间改过。绝不盲目覆盖。用户想重写某一段时，就地编辑那一段，其余不动。

## 不在范围内（out of scope）

- 从料堆之外挖掘新碎片（缺口按「从料堆里取料」处理）。
- 编辑原始素材文件。
- 发布、为特定平台排版，或添加用户没要求的 frontmatter。
