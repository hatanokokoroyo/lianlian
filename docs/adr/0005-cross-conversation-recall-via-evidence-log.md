# 跨会话不传对话历史，靠可查询的依据日志

一个会话内部，历史原封不动地逐轮累加（保前缀缓存命中）；**跨会话时，只有档案投影进入装配**，别的会话的对话历史一个字都不带。第一手信息（"我上厕所蹲不下去"）不塞进装配，而是落成**依据日志**，由 agent 通过 `search_evidence` 工具按需查询。

**理由**：装配里只有结论（`距骨｜活动度=受限`）时，agent 无法生成与之相干的回应——它不知道"蹲不下去"这件事，就想不到去问踝关节。而把全部历史都装进去，上下文会被无关对话撑爆、每轮成本线性增长、且不可复现。

**这是两条记忆通道**：**状态记忆**（档案投影，永远在场，是可复现的当前认知）+ **情景记忆**（依据日志，按需检索，是第一手细节）。人类的工作记忆与检索记忆是同一套分工。

**代价**（接受）：agent 必须在恰当的时机想到去查——写错的工具调用规则会让它看不见关键信息；用户"刚才说到哪了"这类问题在新会话里答不上来（会话内的连续追问不受影响）。

**推论**：依据日志的写作质量就是这套设计的下限。日志必须结构化（用户说法要点 / 验证方案与反馈 / 推理 / 不确定之处），且"敷衍的日志"要在 UI 上暴露给用户看、可被拒绝。

**推论（硬规则）**：`record_finding` / `correct_finding` 之前必须先对该部位调用 `search_evidence`。这条规则**由 Rust 工具层强制**（未查则拒绝写入并回错误），不写在提示词里求模型自觉。

**推论（日志不随会话消失）**：删除会话只删消息正文，依据日志与照片保留，日志里标注"来源会话已删除"；彻底移除要走档案页的重操作。
