# 提示词按"稳定在前、易变在后"排列

每次模型调用的输入顺序固定为：`[系统提示][本会话历史][档案投影 + 训练条件 + 未结提议][用户本轮消息 + 照片]`。

**背景**：DeepSeek 是前缀缓存——命中部分 $0.003/M，未命中 $0.15/M，差 50 倍。而**接受一条提议就会改档案**，这在一次会话里会发生很多次。

**决定**：把易变的档案投影放到历史**之后**。若档案在前，用户一接受提议，整个会话历史的缓存立刻作废；放在后面，只有"档案 + 新消息"这一段重算。

**代价**（接受）：模型先读到一堆历史，最后才知道"现在是什么状态"，所以系统提示里必须显式说明"当前状态在最后一条消息之前给出"，否则它会把历史里的旧判断当现状。这一句是这套排列能成立的前提，属于**不得删改**的提示词内容。

**推论**：会话内历史必须逐轮原封不动地累加——任何"重写历史以压缩上下文"的做法都会让前缀失配，把缓存优化变成负数。
