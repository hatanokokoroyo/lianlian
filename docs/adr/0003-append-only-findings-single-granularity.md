# 档案条目只追加，部位只有一种粒度

`Finding` 一旦写下就永不修改、永不删除：修正走 `Correction` 事件，当前状态是最近事件投影出来的结果。部位只记录到预设词表里的**肌肉或骨骼**这一种粒度，**肌群是查询时算出来的聚合视图**（成员肌肉取最差值），不是可写入的部位。

**理由**：产品的核心承诺是"三个月前说臀弱，现在好了吗"——只有事件流能回答。若允许覆盖，时间线会被悄悄改写，趋势图与 2D/3D 解剖图上的历史状态都会失真。

**为什么不让肌群成为可记录部位**：agent 在对话里说的往往是"臀部偏弱"（一组肌肉）。若允许把肌群写进档案，就会出现"臀部弱"与"臀大肌正常"两条并存且互不矛盾的记录，2D/3D 上无法着色，趋势也无法比较。只存最细粒度、聚合时再算，两种粒度都能展示且不会打架。

**代价**（接受）：写错一条不能删，只能追加更正，UI 必须能把"已被更正的条目"显示得不像事实；词表不全时 agent 无法记录，只能推动词表扩充——因此词表本身是受版本管理的静态数据。

**唯一的例外**：用户手填的身高/体重（`Measurement`）是测量日志而非判定，允许单条删除。
