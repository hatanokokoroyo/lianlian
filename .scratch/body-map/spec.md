# Spec：3D 身体图与档案异常联动

GitHub: #32
Status: ready-for-agent
Type: spec

> 词汇以仓库根 `GLOSSARY.md` 为准；本文出现的每个术语都在词表里。决策以 `docs/adr/0001`–`0007` 为准。

## Problem Statement

档案已经能回答“哪里需要先处理”，但很难回答“那是我身上的哪里”。

- 档案根页列出「需要先处理的肌群」，区域页里有部位卡和五轴，但每一个判定都是文字：臀大肌左侧、腹横肌、多裂肌。用户没法把文字和自己的背、腰、髋对上。
- 2D 身体图已经试过，躯干与深层肌（腹横肌、多裂肌、腰方肌）在平面上只能靠色块和文字解释，背侧与遮挡关系不直观。
- 上一版已经有 3D 解剖 spike，但它和档案没有关系：模型上没有任何“我的问题”；而且点一下肌肉、切一次层级就会重新取景——用户刚放大到肩胛，点个按钮就回到全身。

结果是：要看懂“这三处需要注意”，用户仍然得来回读字，3D 只是一个能转的模型。

## Solution

把 spike 变成产品里的 **3D 身体图**：档案的第三种视图。

1. 档案根页有两个入口：常驻的「3D 身体图」，以及有异常时出现在「需要先处理的肌群」下方的「在 3D 里看这 N 处」。
2. 打开后，模型上直接标出所有异常部位：按部位与侧别染色，红色是需要注意，青/橙是左右；没有异常的肌肉保持中性。
3. 点任意肌肉，底部升起一张卡片：部位名、侧别、五轴状态、最差的一条，以及「只看这块」「在档案里看依据」。不跳页、不打断。
4. 选中深层肌时自动切到“深层”，让腹横肌、多裂肌这类平时被遮住的肌肉真的可见。
5. 相机与可见性彻底分开：点选、切层级、开关卡片都不改缩放与角度；只有首屏加载、重置、「只看这块」有权取景。「只看这块」退出时原样恢复。
6. 有异常时，底部还有一个「需注意 N 处」的列表，按肌群分组；屏幕阅读器用户走这条路径能拿到与画布同样的信息。

## User Stories

### 进入与发现

1. 作为用户，我想在档案根页随时打开「3D 身体图」，这样我不用为了看一眼模型翻进某个区域。
2. 作为用户，我想在「需要先处理的肌群」下方看到「在 3D 里看这 N 处」，这样我知道这些文字对应的是哪几块肌肉。
3. 作为用户，我想只有存在异常时才看到「在 3D 里看这 N 处」，这样没有问题时页面不会被一个空动作占位。
4. 作为用户，我想在没有异常时仍然能打开 3D 身体图，这样我可以把它当解剖图看。
5. 作为用户，我想在空档案时也能打开 3D 身体图且不报错，这样第一次使用不会撞上空白页。
6. 作为用户，我想从档案进入 3D 时不需要再选一次“看哪里”，这样少一步。

### 看懂模型

7. 作为用户，我想异常部位在模型上直接是红色的，这样我不用点开就知道哪里需要注意。
8. 作为用户，我想左右两侧分开着色，这样我能判断异常在哪一侧。
9. 作为用户，我想正常肌肉保持中性颜色，这样红色不会被一堆颜色淹没。
10. 作为用户，我想选中部位与异常颜色有明确区别，这样我能分清“需要处理”和“我正在看”。
11. 作为用户，我想在模型上看到自己全部的异常部位，而不只是当前区域，这样我能形成整体印象。

### 选中与详情

12. 作为用户，我想点一下肌肉就在原地看到说明，这样我不用离开模型。
13. 作为用户，我想卡片里看到部位名和侧别，这样我知道自己点中的是左边还是右边。
14. 作为用户，我想卡片里看到五轴状态，这样我能知道是张力、疼痛还是稳定性出了问题。
15. 作为用户，我想卡片里看到最差的那一条的一句话，这样我不用展开全部依据就能判断。
16. 作为用户，我想点正常部位也有卡片，并明确告诉我“这个部位还没有判定”，这样我不会以为点坏了。
17. 作为用户，我想点空白处、× 或下拉就能关掉卡片，这样关闭方式符合手机习惯。
18. 作为用户，我想卡片只占屏幕一部分，这样我还能同时看着模型。
19. 作为用户，我想选中深层肌时自动切到“深层”，这样腹横肌、多裂肌不会“点了却看不见”。
20. 作为用户，我想在卡片里点「只看这块」，这样我能把目标肌肉从遮挡里剥出来。
21. 作为用户，我想退出「只看这块」后恢复原来的视角和缩放，这样我不会丢失刚才的位置。
22. 作为用户，我想在卡片里点「在档案里看依据」跳到对应区域页，这样我能读完整的证据与时间线。
23. 作为用户，我想从区域页返回时 3D 仍是刚才的视角、缩放和选中，这样我能接着看。

### 相机与缩放

24. 作为用户，我想放大后点别的肌肉，缩放保持不变，这样我不用每次重新找位置。
25. 作为用户，我想切换层级（全身/浅层/深层/骨骼）时角度和缩放不变，这样切换只改变看见什么，不改变我在哪。
26. 作为用户，我想打开或关闭详情卡时模型不跳，这样读字的时候不会失去空间感。
27. 作为用户，我想切正/背/左/右时只是绕当前目标转过去，距离不变，这样我能从同一距离比较不同方向。
28. 作为用户，我想自由旋转后视角按钮显示最接近的那个方向，这样按钮不会说谎，也不会四个都不亮。
29. 作为用户，我想点「重置」回到全身正视，这样我有一个确定的退路。
30. 作为用户，我想缩放有上下限，不会穿进模型里或飞得太远。
31. 作为用户，我想切到别的 Tab 或进出区域页再回来时相机还在，这样应用不会偷偷忘掉我操作到哪。
32. 作为用户，我想冷启动后回到默认视角，这样新一次打开是干净的。
33. 作为用户，我想在从“看这 N 处”进入时默认看到异常所在的那一面，这样红色不会全在背面。

### 异常列表

34. 作为用户，我想在 3D 里打开「需注意 N 处」列表，这样我能按名字找到画布上的红块。
35. 作为用户，我想列表按肌群分组，这样它和档案根页的说法一致。
36. 作为用户，我想点列表里的一行就选中对应部位并定位，这样我不用在模型上猜哪块是它。
37. 作为用户，我想列表里的每一行写明部位、侧别和最差的一条，这样我不进卡片也知道是什么问题。

### 状态与降级

38. 作为用户，我想在模型加载时看到明确提示，这样我不会以为应用卡死。
39. 作为用户，我想在载入失败时看到原因、重试和回档案，这样我有一条路可走。
40. 作为用户，我想在档案读取失败时仍能看模型，并明确知道高亮不可用，这样我不会把“没标红”误当成“没问题”。
41. 作为用户，我想在某个部位缺少模型网格时看到说明，这样它不会从列表里无声消失。
42. 作为用户，我想在设备较慢时自动切到流畅档并被告知，这样我不会对着 15 fps 的模型硬撑。

### 学习与无障碍

43. 作为第一次进入的用户，我想看到一行手势提示，这样我知道可以拖动、缩放和点选。
44. 作为已经会用的用户，我想这行提示不再出现，这样它不会一直占地方。
45. 作为使用屏幕阅读器的用户，我想通过「需注意 N 处」列表拿到与画布相同的信息，这样 3D 不是唯一入口。
46. 作为用户，我想所有按钮都有足够大的触控区域，这样单手操作不会点空。

## Implementation Decisions

### 信息架构与入口

- 不新增底部 Tab。3D 身体图是档案栈内的全屏页，标题「3D 身体图」。
- 档案根页右上角常驻文字按钮「3D 身体图」，替换现有的「3D 解剖 spike」。
- 「需要先处理的肌群」块底部增加一行「在 3D 里看这 N 处 ›」，仅当存在异常时出现；`N` 是异常部位卡数，与档案根页的计数口径一致。
- 两个入口 push 同一个页面；后者带 `focus=attention`，进入时打开异常列表。
- v1 不做区域页反向入口，避免 3D → 区域页 → 3D 的返回环。
- 3D 页面属于详情页，进入后底部 Tab 收起，沿用现有行为。

### 高亮模型

- 高亮粒度是**部位 + 侧别**，与档案读模型的粒度一致；不引入肌群级染色，也不新增领域粒度。
- 异常：统一使用主题的 `destructive` 色，不按严重度分级。严重度由卡片里的轴列表和列表里的异常处数承担。
- 正常：保留左右底色（左青、右橙），中性、低饱和。
- 选中：使用 `primary` 提亮，并在卡片中说明侧别；不用 `accent`，因为左侧底色已经占用了它。
- 主题色由原生侧传入 WebView；viewer 内不得写死十六进制颜色。
- 不靠颜色单独传达含义：异常列表里有文字，卡片里有侧别。

### 选中与详情卡

- 点选部位不跳页、不取景，只改变高亮与卡片。
- 选中携带部位与侧别：点哪一侧就选中哪一侧；程序化选择（URL、异常列表）可以只给部位，此时按双侧处理。卡片优先取同侧卡；没有同侧卡时明确说明「这一侧还没有判定」。
- 卡片从底部升起，占屏高约四成，可滚动、可下拉关闭；点画布空白或 × 也关闭。
- 卡片内容顺序固定：中文名 + 侧别 → 五轴状态 → 最差的一条 → 主按钮「只看这块」、次按钮「在档案里看依据 ›」。
- 点正常部位同样出卡片，显示「这个部位还没有判定」，不出现红色。
- 选中深层肌时自动把层级切到“深层”；控件状态同步变化。这是可见性变化，不是取景。
- 「只看这块」保存当前相机与层级，取景该部位并只显示它（同一部位的多块网格一起显示）；退出时原样恢复进入前的相机、层级与选中。
- 「在档案里看依据」push 对应区域页并带 `focusSlug`；返回时恢复 3D 页面的相机、选中与层级。

### 相机契约（ADR-0007）

| 动作 | 相机 | 可见性 |
| --- | --- | --- |
| 首屏加载 | 取景全身，仅一次 | 全身 |
| 拖动 / 双指缩放 | 完全交给用户 | 不变 |
| 切视角 正/背/左/右 | 绕当前目标旋转到该方向，保持距离与目标 | 不变 |
| 切层级 全身/浅层/深层/骨骼 | 不动 | 变 |
| 点选 / 取消选中 / 开关卡片 | 不动；卡片不得改变画布尺寸 | 变 |
| 只看这块（隔离） | 显式取景该部位；退出时原样恢复 | 只留该部位 |
| 重置 | 取景全身 | 全身 |
| 从区域页返回或切 Tab 回来 | 恢复上次相机、选中、层级 | 恢复 |
| 自动降档 | 不动（保留相机、选中、层级） | 变 |

配套约束：所有覆盖层绝对定位，不参与画布布局；打开卡片时不做投影偏移；关闭缩放手势的“以指针为中心”行为，避免缩放在用户不知情时改变相机目标；缩放上下限按当前取景距离的固定比例计算，且不随选中变化。

### 页面结构与控件

- 顶栏：左「← 档案」，标题「3D 身体图」，右「重置」。
- 画布铺满内容区。控件浮在底部安全区之上，分两行：
  - 第一行：视角四段选择（正/背/左/右），高频，拇指可达。
  - 第二行：左「层级：<当前> ▾」菜单（全身/浅层/深层/骨骼）；右「需注意 N 处 ›」胶囊，仅在存在异常时出现。
- 移除 spike 的模型档位切换、自转、渲染统计与三个快捷目标；档位由设备策略自动决定。
- 首次进入在画布底部显示一行「拖动旋转 · 双指缩放 · 点肌肉看详情」，首次成功交互后淡出，之后不再出现；v1 不做帮助页。
- 图例不常驻画布，只在异常列表表头出现「红＝需要注意 · 青/橙＝左/右」。

### 初始视角与视角状态

- 默认正视。
- 从「在 3D 里看这 N 处」进入时，若背侧异常部位占多数，默认背视；否则正视。
- 自由旋转后，视角选择按相机当前方向高亮最接近的正/背/左/右；旋转停止后更新。任何时刻都有一个按钮处于选中态。

### 异常列表

- 从「需注意 N 处」打开，按肌群分组，组内按部位排序。
- 每行：部位中文名、侧别、最差的一条（轴 + 取值）；与档案根页「需要先处理的肌群」的写法一致。
- 点一行：选中该部位、必要时切换层级、收起列表并打开详情卡。
- 缺少模型网格的部位保留在列表里，标「模型里暂缺」，且不能执行「只看这块」。

### 设备档位与降级

- 默认使用视觉档（原始几何）。
- 模型就绪后连续采样约 2 秒帧率：低于 24 fps 时自动切到 3,000 档；再低于 20 fps 时切到 2,000 档。
- 切档保留相机、选中与层级；只显示一次安静提示「已切到流畅档」，不弹窗、不阻断。
- 2,000 档仍低于 20 fps 时，在顶栏下方给一行「这台设备可能较慢」并提供回档案入口，不假装流畅。

### 状态设计

- 加载：画布区域显示主题底色与「正在载入身体模型…」，不显示百分比进度；超过 3 秒追加「设备较慢时，可以先回档案页看依据」。
- 空档案：模型正常显示，无红色、无「需注意」胶囊；点任意部位显示「这个部位还没有判定」。
- 载入失败 / WebGL 不可用 / 内存不足：整页错误态，标题「3D 身体图没能载入」，一句人话原因，主按钮「重试」，次按钮「回档案」。
- 档案读取失败但模型正常：模型可看，关闭高亮，顶部一行「档案没读出来，现在只显示解剖图」并提供重试。
- 缺网格：见异常列表。

### 状态边界

- 相机、选中、层级、视角在同一个 App 会话内跨页面、跨 Tab 保留。
- 冷启动重置为「正视 · 全身 · 无选中」。
- 不写盘，避免“上次看到哪”变成隐式状态。
- 顶栏「重置」是唯一不靠手势的退路，清除相机、选中与层级。

### 骨骼与范围

- v1 只给肌肉染异常色；骨骼层级仍可查看（灰白参考），不参与异常高亮，也不加骨性标记点。
- 骨骼异常继续在档案页与区域页正常显示。

### 映射与数据

- `node -> site_id` 以稳定的映射文件为唯一来源，不依赖节点名、节点顺序或 GLB 中的额外属性。
- 一个部位可以对应多个网格对象；可见性、隔离与高亮按部位聚合。
- 9 个骨性标志不参与本功能。
- 3D 身体图只读：不产生档案条目、不改判定、不新增存储，也不改变判定粒度。

### 无障碍

- 画布提供整体描述性标签；异常列表是画布的非视觉等价路径，信息不得只存在于画布。
- 所有按钮与列表行触控区域不小于 44×44。
- 卡片打开时把焦点移入卡片，关闭时回到触发它的部位或列表行。

### 文案

- 入口与标题：「3D 身体图」。
- 界面使用「需要先处理」「需要注意」「异常」，不用“有问题”“病灶”。
- 卡片与列表沿用档案现有的部位中文名与侧别写法。

## Testing Decisions

好的测试只断言外部行为：给定一次操作，状态机输出哪些“取景/可见性/高亮”命令，以及页面显示了什么。不断言 Three.js 内部对象、材质或像素；布局与观感由真机截图人工验收，自动化测试不冒充它。

### 主要测试接缝

- **接缝一（主）：不依赖 WebGL 的 viewer 状态机。** 把“取景/可见性/选中/降档”的决定从渲染代码里剥出来，做成纯函数或 reducer，输入是当前状态与动作，输出是新状态加命令列表。取景契约的全部规则只在这一层断言：点选不产生取景命令、切层不产生、切视角产生“保持距离的旋转”、隔离产生“保存 + 取景”、退出隔离产生“恢复”、降档不产生。现有 spike 把这几件事缠在同一个取景函数里，是本功能最需要先拆的地方。
- **接缝二：viewer 对外协议。** 原生页面与 viewer 之间只通过少量命令与一份状态快照交互：载入、恢复状态、设置异常部位集合、选中、清空、切视角、切层级、隔离、重置、读取统计。用现有的无头浏览器校验扩展覆盖：高亮集合等于异常集合；选中后相机位置与距离不变；切层后不变；隔离后再退出可恢复；正常部位卡片内容正确；缺网格部位出现在列表里。现有脚本已经验证过模型档位、四个视角、三个目标部位与隔离，直接在其上加断言，不新建一套。
- **接缝三：档案页入口与导航（屏幕级）。** 沿用现有档案页测试的写法：有异常时出现「在 3D 里看这 N 处」且 N 与异常卡数一致；无异常时不出现；两个入口都进入 3D 页面，后者带关注参数；返回后根页状态不变；3D 页的加载、空、错误、读失败四态在原生调用被替换时各自可见。
- **接缝四：映射数据完整性。** 每个有判定的肌肉部位至少映射到一个网格对象；没有节点被映射到两个部位；9 个骨性标志不出现在肌肉映射里；缺网格的部位能被列表识别。现有 GLB 校验脚本已经覆盖节点数与映射一致性，扩展它即可。

### 先行与回归

- 先写状态机测试，再改 viewer；这是唯一能在没有真机的情况下锁住“缩放不重置”的地方。
- 屏幕级测试与档案页现有用例共用同一套造数据方式，不引入新的测试数据库。
- 每次改动 viewer 后重跑无头校验，确认档位、视角、隔离与本次新增的高亮集合断言都通过。

## Out of Scope

- 骨骼异常高亮与骨性标记点。
- 区域页反向进入 3D 的入口。
- 冷启动恢复上次相机。
- 左右分屏或两档模型对比。
- 原生 GL / Gradle 宿主方案。
- 2D 身体图 fallback。
- 英文/拉丁名、语音、分享与导出。
- 多机型性能矩阵与正式定量验收（见 Further Notes）。
- 用户自定义颜色、主题或模型外观。
