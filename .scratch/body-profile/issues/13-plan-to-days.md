# 13: 计划展开到训练日与改期

**What to build:** 把计划的频次规则展开成日历上的具体**训练日**：按规则排出未来若干天，单日可手动改到别的日期；每个训练日存**动作快照**而不是指向计划版本的引用（改计划不得篡改历史）。

**Blocked by:** #3, #8

**Status:** resolved

- [x] 单日可改期到另一天，改期后原日恢复为休息日
- [x] 计划被改成新版本后，已存在的训练日动作快照不变
- [x] 未来训练日在日历数据里可查询

**2026-11-16 评审补丁（agent）**

- 术语统一到词表：`reschedule` / `改期` / `moved_from` 全部改为 `postpone` / `推迟` /
  `postponed_from`（`api::Days.postpone`）；GLOSSARY「推迟」下写明 _Avoid_: 改期、延后。
  推迟后新那天的日状态仍是「计划中」——「已推迟」描述的是原来那天，留给 #15 的占位行。
- 修正「不连排」的说法：七天是循环，循环里最多 3 个互不相邻的位置，所以 1–3 次才保证
  不连排；4 次的固定作息是一/三/五/日，唯一那对相邻落在周日 → 下周一（周内仍是均匀的）。
  注释、README 与测试（含跨周断言与四周相邻位置）都改了。
- `Days.range(today, from, to)` 接收设备本地的今天：此前用 UTC 的 `now_ms()` 判断「只往未来
  展开」，UTC+8 的清晨会把本地昨天当成未来而补出一行「计划中」。
- 日期末端的毫秒收口成 `Date::end_ms()`，api 两处重复的算法删掉。
