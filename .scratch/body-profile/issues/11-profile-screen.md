## 交付记录（#11）

- `domain/archive.rs`：档案页的读模型，纯函数、零 IO。从事件流 + 依据日志算三样东西——
  按区域分好的卡片（肌肉跟首要肌群、骨骼跟区域，左右各一张，中线一张）、每行的四段依据与倒序时间线、
  肌群聚合（成员逐轴取最差值并指名来源）。词表外的 id 直接被跳过（旧库 / 手改 JSON 的防线）。
- `api::Findings`：`load()` 读整个读模型；`resolve(finding)` 追加一条正常判定（`FindingDraft::resolve`）；
  `retract(finding, reason)` 撤回，理由空白直接拒。两个动作都走 `store::evidence` 的
  `record_with_evidence` / `retract_with_evidence`（判定与依据同一事务），依据里如实写
  「未经 agent 验证 / 未经复查」——它们是用户的动作，不冒充一次验证。
- `screens/findings.tsx`：档案条目区。五轴标签（未测虚线、异常 destructive）、展开看四段依据、
  时间线（最近在前、撤回带理由、当前生效标出来）、「标记已解决 / 判定有误」、肌群整体（成员最差值 +
  来源部位）、空档案引导去首次评估。列表与条件用 `Each` / `If`（按 key 保行）；撤回理由表单摆在
  列表上方，不塞进会重排的行里。
- `screens/profile.tsx`：档案页改成「档案条目在前、基本属性/测量/训练条件在后」，标题与说明跟着改；
  `ui/dates.ts` 抽出日期格式（测量页与档案页共用）。
- 测试：`cargo test` 193 项、`nsh test` 205 项（1 skipped）；新增 `Findings.test.tsx` 覆盖
  「通过提议卡真实落 3 条判定 → 分组与左右分开 → 展开四段依据 → 时间线 → 已解决后历史仍在 →
  撤回必须写理由且撤回到消失 → 肌群聚合指名最差值 → 重开仍在」与「空档案引导去首次评估」。
- 视觉契约：`design/contract.md` §7 档案一行按实现补齐 testID；§9 记两条偏差（来源会话链接与
  修改训练条件的入口另开工单、撤回表单的位置）。
- 没有改库结构，`schema_version` 不变（10）。
