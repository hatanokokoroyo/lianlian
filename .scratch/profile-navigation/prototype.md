# 档案页信息架构原型（throwaway）

**问题**：档案根页随档案条目变长。先把根页收成摘要/目录，档案条目按区域进子页；
验证三种根页结构哪一种更顺手。

**结论（2026-11-17）**：采用 **D · 组合**。顺序为生效计划 → 需要先处理的肌群 → 全部区域 →
我的数据；spec 见 `spec.md`。A/B/C 只保留作对比，不进实现。

## 入口

- 原型：`design/screens/profile-ia-prototype.html`
- 索引：`design/screens/index.html` 底部的「档案信息架构原型（throwaway）」
- 直达：`#variant=A|B|C`；区域页 `#variant=A&section=gluteal-group`；计划页 `#variant=A&page=plan`
- 交互：底部浮动条或键盘 ← / → 切换；区域行进入区域页；返回键回根页；C 变体的筛选可用。

## 四个变体

| 变体 | 根页结构 | 主要检验 |
|---|---|---|
| A · 目录 | 计划卡 → 单列区域索引 → 我的数据 | 最保守的目录结构，根页长度只随区域数增长 |
| B · 关注优先 | 异常摘要 → 2 列区域网格 → 计划条 → 我的数据 | 用户先看“哪里需要注意”，再按区域进入 |
| C · 筛选 | 类型/异常筛选 → 密集区域列表 → 计划条 → 我的数据 | 区域多起来后，筛选是否比长索引更省事 |
| D · 组合（默认） | 计划卡 → 需要先处理的肌群 → 全部区域网格 → 我的数据 | 把 A 的计划位置、B 的关注摘要和完整区域索引合成一页 |

共享子页：区域页（部位卡、五轴、依据展开、时间线入口）、计划页（动作 → 判定）、
我的数据占位页。导航统一是 `NavStack` push 的心智模型。

## 需要记住的领域事实

真实读模型 `ProfilePage.sections` 不是 8 个身体区域：肌肉按**首要肌群**分（23 个），
骨骼按**解剖区域**分（8 个），且只出现有生效判定的区域。原型用 10 个有代表性的区域做样本。
如果根页要收成更粗的“8 个身体区域”，需要额外一层肌群 → 身体区域的映射，属于新决策。
