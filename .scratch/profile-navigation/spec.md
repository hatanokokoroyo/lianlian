# Spec：档案页信息架构（profile-navigation）

GitHub: #27
Status: ready-for-agent
Type: spec

> 词汇以仓库根 `GLOSSARY.md` 为准；本 spec 采用已选定的 **D · 组合** 原型。
> 决策沿用 ADR-0003（档案条目只追加、读模型从事件流算出）与 ADR-0005（依据日志跨会话保留）。

## Problem Statement

档案条目会随对话持续增长。现在档案根页把计划卡、全部部位卡、基本属性、测量、训练条件和本地数据
放在同一个滚动页里；用得越久，根页越长，打开档案后第一屏被历史判定占满，用户很难快速回答：

- 我现在在练什么？
- 哪里需要先处理？
- 某个部位在哪里、怎么进去？
- 身高体重、训练条件、本地数据在哪里改/看？

这不是静态区块太多，而是**档案条目没有分层**：根页承担了索引和详情两种职责。

## Solution

把档案根页收成稳定的摘要/目录页，档案条目的详情按现有区域粒度进入子页：

1. **生效计划**放在最上面：版本、频次、复查日、动作数；点进独立的计划页看完整动作与历史版本。
2. **需要先处理的肌群**：只列有异常判定的肌群，显示最差的那一条与异常处数；点进该区域的区域页。
3. **全部区域**：现有粒度的区域索引（肌肉按首要肌群、骨骼按解剖区域），只显示有生效判定的区域；
   每块显示条数、最差状态/最近时间；点进区域页。
4. **我的数据**：基本属性、测量、训练条件、本地数据各一行摘要，进入各自子页。

区域页保留现有的部位卡、五轴、依据展开、时间线、标记已解决与判定有误；根页不再渲染单条部位卡。
根页长度只随区域数量增长，而区域数量受解剖词表限制，不再随判定历史无限增长。

## User Stories

1. 作为用户，我想打开档案先看到当前生效计划，这样不用穿过所有判定才知道自己在练什么。
2. 作为用户，我想在生效计划摘要里看到版本、频次、复查日和动作数，这样我能判断计划是否还适合现在。
3. 作为用户，我想点计划摘要进入计划页，这样我能看到完整动作清单和历史版本。
4. 作为用户，我想在计划页点某个动作的「看判定」直接到对应区域，这样我知道为什么做这个动作。
5. 作为用户，我想进入区域页时自动展开对应的部位卡并打开时间线，这样不用再找一遍。
6. 作为用户，我想在根页先看到需要处理的肌群，这样我知道这次该先关注哪里。
7. 作为用户，我想每个需要处理的肌群显示最差的那条判定和异常处数，这样我知道它为什么被标出来。
8. 作为用户，我想点需要处理的肌群进入区域页，这样我能看完整依据并决定是否更正。
9. 作为用户，我想在根页看到全部有判定的区域，这样我能找到没有出现在「需要先处理」里的部位。
10. 作为用户，我想每个区域显示条数、当前最差状态和最近更新时间，这样我能快速比较。
11. 作为用户，我想点任意区域进入区域页，这样根页不会一次铺开所有部位卡。
12. 作为用户，我想区域页只显示该区域的部位卡，这样页面长度有界。
13. 作为用户，我想区域页保留五轴、依据展开、时间线、标记已解决和判定有误，这样现有操作不丢。
14. 作为用户，我想从区域页返回根页，这样我能继续看别的区域。
15. 作为用户，我想肌群区域页显示成员最差值的聚合，骨骼区域页显示区域整体最差，这样聚合标题不会串。
16. 作为用户，我想基本属性在独立子页编辑，这样根页不会带着长表单一起滚动。
17. 作为用户，我想基本属性子页保存后根页摘要更新，这样我不用回根页再手动刷新。
18. 作为用户，我想测量继续在现有测量页看趋势，根页只显示当前身高/体重摘要。
19. 作为用户，我想训练条件在独立子页编辑，根页显示齐全/不齐全和缺项摘要。
20. 作为用户，我想本地数据在独立子页看容量明细，根页只显示已用总量摘要。
21. 作为用户，我想设置仍然从根页进入，这样模型 key 的入口不变。
22. 作为用户，我想没有档案条目时根页仍然给出首次评估入口，而不是空索引。
23. 作为用户，我想没有生效计划时看到明确的「还没有计划」而不是空白。
24. 作为用户，我想读库失败时在根页或对应子页看到错误，而不是装作空档案。
25. 作为用户，我想骨骼区域的异常仍然在「全部区域」里标出，即使它不出现在「需要先处理的肌群」里。
26. 作为用户，我想已解决的部位仍然留在区域页里，这样我能回看它曾经被处理过。
27. 作为用户，我想根页的区域条数与区域页里的卡片数一致，这样摘要不会骗我。
28. 作为用户，我想区域页在最后一条判定被撤回后给出空态，这样我不会看到一片空白。
29. 作为用户，我想系统返回键从任意子页回到上一级，这样导航符合 Android 习惯。
30. 作为用户，我想切到底部其他 Tab 再回来时档案页仍从根页开始，这样不会迷失在旧子页。

## Implementation Decisions

### 信息架构与路由

- 档案页根页按 **D** 的顺序组织：头部/设置入口 → 生效计划摘要 → 需要先处理的肌群 → 全部区域索引 →
  我的数据。根页不渲染任何单条部位卡。
- 采用现有区域粒度：`SiteSection` 仍然是「肌肉按首要肌群、骨骼按解剖区域」。不新增更粗的身体区域层，
  不做搜索或筛选（C 变体不采用）。
- 档案页路由从现有的 `root | measurements | settings` 扩展为：
  `root`、`section(sectionId, focusSlug?)`、`plan`、`basics`、`measurements`、`training`、`storage`、`settings`。
  全部用现有 `NavStack` / `NavPage` push；系统返回键与页面返回按钮逐层回退。
- 切换底部 Tab 不保存档案子页位置：再回档案从 `root` 开始（与现有每个 Tab 自己一个页面栈的行为一致）。

### 读模型与区域种类

- `SiteSection` / `SiteSectionView` 增加 `kind: "muscle" | "bone"`。这是只读模型的附加字段，
  不改事件流、不改存储、不改判定语义；用于：
  - 根页「需要先处理的肌群」只筛 `kind == "muscle"` 的异常区域；
  - 区域页聚合标题区分「肌群整体」与「区域整体」；
  - 全部区域索引可以显示「肌肉 / 骨骼」。
- 「异常」沿用现有五轴读模型：只要一张 `SiteCardView` 的任一轴 `abnormal` 为真，这个部位就算需要注意。
  区域摘要中的「N 处」按异常卡片数计，不按异常轴数计。
- 区域摘要的「最差一条」按以下顺序选一张卡：异常轴数量最多 → 当前判定时间最新；
  文案使用 `部位中文名 + 侧别 + 轴名 + 取值`，与现有五轴显示一致。
- 根页的区域索引只显示 `FindingsView.sections` 里已经有生效判定的区域；没有判定的区域不出现。
  已解决但仍有生效判定的区域仍然出现。

### 根页组件

- 根页拥有 `Findings` 读模型（总数、区域、肌群聚合）和 `Plans` 读模型（生效计划、历史版本）；
  这两个资源提升到档案页层级，根页与子页共享同一份快照，区域页完成更正后重取，根页返回时看到新状态。
- 生效计划摘要显示：版本、频次、复查日、动作数；有 `reviewDue` 时沿用现有的复查提示语气。
  没有生效计划时显示「还没有计划」和去对话的入口，不显示空卡片。
- 「需要先处理的肌群」只列异常肌群；每行显示区域名、最差判定、异常处数；点击进入区域页。
  没有异常肌群时显示一句「目前没有需要优先处理的肌群」，不占大块空间。
- 「全部区域」使用双列网格（D 原型），每块显示区域名、条数、最差状态/最近时间；异常区域有明确描边。
- 「我的数据」四行：基本属性、测量、训练条件、本地数据。每行显示摘要和动作词（编辑/趋势/修改/查看），
  点击进入对应子页。

### 区域页

- 区域页接收 `sectionId`，可选 `focusSlug`。找到区域后显示区域名、种类、判定数与异常数。
- 肌群区域页展示该肌群的聚合行（成员最差值，左侧/右侧各自聚合）；骨骼区域页展示该区域的最差一条。
- 区域页复用现有部位卡的全部行为：五轴、依据展开、时间线、标记已解决、判定有误与撤回理由。
- 从计划页带 `focusSlug` 进入时，自动展开该部位卡并打开时间线；找不到对应卡片时给出明确提示。
- 最后一张生效判定被撤回后，区域页显示「这个区域已经没有生效判定」并提供返回根页；
  不自动弹回根页，避免用户来不及看见结果。
- 区域页的错误态、读库失败与现有档案条目区保持一致；不把错误伪装成空区域。

### 计划页

- 计划页显示生效计划的完整动作清单（名称、处方、来自哪条判定）与历史版本只读列表；
  保留「看判定」入口，点击后找到包含该 `slug` 的区域并 push 区域页，带上 `focusSlug`。
- 计划页的错误态与空态单独显示；没有生效计划时不展示空动作列表。

### 我的数据子页

- 基本属性与训练条件从根页搬进独立子页，复用现有草稿与保存接口；保存成功后重取 `ProfileView`，
  返回根页时摘要已更新。
- 测量页与设置页保持现有实现；根页的测量摘要显示当前身高/体重与「趋势」入口。
- 本地数据从根页搬进独立子页，复用现有容量读取与表格；根页只显示已用总量摘要。
- 所有子页都显示返回入口，并让系统返回键沿 `NavStack` 回退。

### 空态、错误态与文案

- 没有档案条目：根页显示现有首次评估空态，并隐藏空区域索引。
- 没有生效计划：根页显示计划空态；计划页显示「还没有计划」而不是空动作列表。
- `Findings` / `Plans` / `Storage` 读库失败：在根页对应区块显示错误；子页继续显示自己的错误态。
- 区域索引条数、异常数与区域页实际卡片一致；测试必须覆盖这一致性。
- 文案沿用 `GLOSSARY.md`：档案、档案页、区域、肌群、档案条目、计划、测量、训练条件；不把区域叫成
  「分类」「部位组」「身体区域」。

### 文档与契约

- 更新 `GLOSSARY.md`：
  - 「档案页」改成根页摘要 + 区域页的读法；
  - 「区域」补充「根页只显示索引，区域页显示该区域的部位卡、依据与时间线」；
  - 新增「区域页」：档案页的子页，展示一个区域的部位卡与时间线。
- 不新增 ADR：这是屏幕信息架构，沿用 ADR-0003 的读模型与 ADR-0005 的依据日志语义。
- 视觉契约的 testID 继续使用现有语义命名；新增根页/子页入口时补登记，不改已有 `site-*`、`group-*`、
  `timeline-*`、`plan-exercise-*` 的命名。

## Testing Decisions

- **唯一接缝**：继续用 App 级 `nsh test`，通过 `open("./App.tsx")` 驱动，配合
  `ensureOnboarded` / `freshDatabase` / `setApiKey`。不新增组件级测试，不把测试绑到内部组件树。
- 好测试只断言用户可见行为：根页能看到什么、点进去看到什么、返回后回到哪里、摘要数字与子页内容一致。
  不断言 `FindingsSection` 是否拆成两个组件，也不断言资源加载顺序。
- 现有测试的更新范围：
  - `Findings.test.tsx`：先点区域进入区域页，再做依据、时间线、解决与撤回；删除根页折叠断言，
    改成「进入区域 → 看到该区域卡片 → 返回根页」。
  - `Plan.test.tsx`：根页只断言计划摘要；点计划进入计划页后再断言动作与版本；
    「看判定」改为断言进入区域页并打开时间线。
  - `App.test.tsx`：基本属性与训练条件改为进入子页填写/保存；根页摘要断言保留。
  - `Measurements.test.tsx` 与 `Navigation.test.tsx`：测量页返回目标改为根页摘要，不再等 `save-basics`。
  - `Storage.test.tsx`：先进入本地数据子页再断言容量表；根页只断言已用总量摘要。
  - 新增 `ProfileNavigation.test.tsx`：覆盖 D 的完整路径——根页顺序、关注肌群、全部区域、
    区域页进入/返回、计划页进入/返回、我的数据四行进入/返回、空档案与无计划状态。
- 计数一致性测试：种入不止一个区域的判定后，断言根页某个区域的「N 处」与区域页里对应卡片数一致；
  断言关注肌群只包含肌肉区域，骨骼异常仍在全部区域里标出。
- 先例：`Profile.test.tsx` 的 `tab-profile` 进入与摘要断言、`Findings.test.tsx` 的提议卡落库路径、
  `Plan.test.tsx` 的计划生成路径、`Navigation.test.tsx` 的 `app.back()` 返回路径。

## Out of Scope

- 不采用 C 变体的搜索/类型筛选；区域数量增长到需要筛选时另开 spec。
- 不引入更粗的 8 个身体区域映射；继续用肌群/骨骼区域作为索引层。
- 不改变 `ProfilePage` 的投影、聚合、时间线、解决/撤回语义，也不改变事件存储格式。
- 不改变计划生成、版本化、复查日、训练日展开与打卡逻辑。
- 不改变测量页、设置页的功能与布局，只调整根页入口摘要。
- 不做新的动效、转场或骨架屏；沿用现有页面切换与加载文案。
- 不做跨 Tab 深链（例如从计划页直接打开某个会话）；保持现有设置入口与对话入口。

## Further Notes

- 选型依据：`design/screens/profile-ia-prototype.html` 的 `D · 组合` 变体；A/B/C 只作对比，不进实现。
- D 的顺序是：生效计划 → 需要先处理的肌群 → 全部区域 → 我的数据。根页不再出现单条部位卡。
- 现有 `archive-section-{id}` 仍作为区域索引的 testID；它从「折叠标题」变成「进入区域页」。
- 现有 `site-*`、`group-*`、`timeline-*`、`plan-exercise-*` 的 testID 保留在区域页/计划页，
  这样更正与计划的回归测试不需要重新发明选择器。
