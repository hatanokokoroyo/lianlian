和现在的页面比，改了什么

常驻慢设备条 + 回档案→2.5 秒 toast + 顶栏状态点
青/橙左右对半分色→暖象牙底色 + 珊瑚异常

点选后卡片盖住部位→相机上移/缩小，部位在卡片上方
深层异常在全身里消失→「深层 2」提示 + 一键切深层

三个可以直接照做的交互

1. 点标记：只换 focus pill 和标记环，不打开大卡片；再点「查看」才展开。
2. 点清单行：切到该部位的 3D 取景，sheet 收成 39% 的详情卡；关闭后回到清单。
3. 深层异常：全身里用「深层 · 未显示」芯片提示；点击自动切深层，不让用户找不存在的红点。

性能边界

原型里的 Standard + ACES 是质量目标；落地时保留 BatchedMesh 的 3 个 draw call，先在中端机测 30fps。若掉帧，退回 Lambert，只改 palette、光照强度和 tone mapping，不动几何与合批。

不是把颜色调亮，是把信息层级调对

左边是现在：8 条档案数据都在，但 12 个异常对象全是白色。右边是建议：正常肌肉回到暖象牙，异常只留珊瑚红；红只出现在该出现的地方。

  • 底色：#cbbeb0 / #b3a798，接近解剖图谱的肌肉与骨骼。
  • 信号：#e15e3f，只给异常；选中用 #d8e567，少量使用。
  • 光影：key / fill / rim 三灯 + ACES，前后面都不爆白；保留肌肉纹理。
  • 标记：编号只出现在当前视角可见的部位；背面 5 处用「背面 5 ›」承接。

先看结论

What to fix first
P0 · 今天

把 8 位 hex 归一化成 6 位

在 native → viewer 的边界裁掉 alpha，或在 toColor() 里统一成 #rrggbb。这是「异常红完全不可见」的唯一根因，不是性能、不是光照。

P0 · 今天

打开卡片时，让相机给部位让位

现在 55% 屏高的清单/详情卡会盖住被选中的臀肌。sheet 打开时把 model 上移或缩小，保证选中区域在卡片上方仍有 ≥ 25% 画布高度。

P0 · 今天

慢设备提示别常驻

「这台设备可能较慢」现在占一整条 48px 顶栏，还带一个重复的「回档案」。改成 2.5 秒 toast + 顶栏一个小状态点，只在降档时出现一次。

一句话：这次不是「再调好看一点」，而是先把已经算出来的异常信号真正画出来；在这个基础上，再把霓虹双色换成更接近医学图谱的暖色体系。

模拟器取证

Android 15 · WebView 124 · 1080×2400

入口：档案 → 3D 身体图。数据是真实的 8 条判定，不是 mock 截图。模型在 cap2000 档：541,822 面、3 draw calls、12 个异常对象。

根因：颜色在进入 Three 之前就丢了

Reproduced on device
// 原生侧 token → viewer 的实际值
palette.left      = "#6ee7f0ff"   // 8 位 hex
palette.abnormal  = "#ff6b6bff"

// viewer 的 toColor()
new THREE.Color("#ff6b6bff").getHexString()
// → "ffffff"

new THREE.Color("#ff6b6b").getHexString()
// → "ff6b6b"

// 实测：8 条判定 → abnormalObjectCount = 12
// 但 BatchedMesh 的 instanceColor 全是 (1,1,1)

为什么之前没发现

0.4.0 的 spike 截图用的是 6 位 hex，所以青/橙/红都正常；接主题 token 之后变成了带 alpha 的 8 位串，Three 不报错，只是静默退回白色。数据层、聚合层、deriveAbnormalSites() 都是对的，只有最后一步着色失败。

#ff6b6bff → 白 #ff6b6b → 珊瑚红 #cbbeb0 → 暖象牙

修复不需要改数据模型，也不需要重导 GLB；在边界裁掉 alpha 即可，零性能成本。

方向：医学图谱，不是霓虹玩具

Design direction
01

中性解剖底色

肌肉用暖象牙，骨骼用浅沙。先让形体、纹理和光影说话；左右不再把人体对半染成青/橙。侧别用文字芯片表达。

02

一个信号色

珊瑚红只给「需要注意」。配柔和光晕、编号标记和一句摘要；不在正常肌肉上铺第二、第三种高饱和色。

03

信息分层

顶部一句「8 处 · 7 个肌群」，底部一条图例，模型上最多 4 个标记。详细依据留给卡片，不堆在画布上。

04

卡片让位

先看部位，再看解释。sheet 打开时相机上移/缩小；深层异常自动切深层，不让用户在「全身」里找一个永远找不到的红点。

验证与边界

What is proven / what is not

已经在模拟器里验证

8 条判定 → 7 个肌群 → 12 个异常对象；cap2000：541,822 面、3 draw calls；WEBGL_multi_draw 可用；8 位 hex 在 Three 中解析为白色；换成 6 位后正/背面 12 个对象全部着色；深层预设可见多裂肌。

还没验证 / 不要过度承诺

模拟器是 SwiftShader，fps 不代表真机；目标机 30fps、连续 30 秒发热、APK 增量、点击高亮延迟仍未测。Standard 材质的帧率要在目标机复测，掉帧就回退 Lambert。模型的手/头问题是数据本身，不是本轮 UI 能彻底解决的。
