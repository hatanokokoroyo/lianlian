# 测试驱动开发

TDD 就是红 → 绿循环。本技能是让这个循环产出**值得留下**的测试的参考：什么算好测试、测试放在哪、有哪些反模式，以及这个循环的规则。每一节都适用于每一次循环：**在循环之前和之中**查阅它们，而不是之后。

探索代码库时，读 `GLOSSARY.md`（若存在），让测试名和接口词汇与项目领域语言一致；并遵守你所触及区域的 ADR。

## 什么算好测试

测试通过公开接口验证行为，而不是验证实现细节。代码可以整体重写，测试不该变。好测试读起来像一份规格说明：「用户可以用有效购物车结账」精确告诉你存在哪种能力，而且它能熬过重构，因为它不在乎内部结构。

示例见 [tests.md](tests.md)，mock 相关规范见 [mocking.md](mocking.md)。

## 接缝：测试放在哪

**接缝（seam）** 是你做测试的公开边界：在那个接口上，你不伸手进去就能观察到行为。测试长在接缝上，绝不针对内部实现。

**只在事先商定的接缝上测试。** 写任何测试之前，先写下被测的接缝并与用户确认。未经确认的接缝不写测试。你不可能测遍一切，所以事先商定接缝，正是让测试精力落在关键路径与复杂逻辑、而不是每个边界情况上的方式。

问：「公开接口是什么，我们该测哪些接缝？」给每个提议的接缝一行说明：它能抓住什么、漏掉什么。

当这个接口的形状本身存疑时（模块该有多深、接缝该在哪、接口该暴露什么），调用 Skill 工具加载 "codebase-design" 取词汇。它是 module、interface、depth、seam、adapter、leverage、locality 这些术语的共同权威，是查阅用的参考，不是要跑的一场会话。

## 反模式

- **与实现耦合**：mock 内部协作者、测试私有方法，或通过旁路验证（查数据库而不是走接口）。识别特征：重构时测试就红，而行为并未改变。
- **同义反复**：断言按代码的做法重算期望值（`expect(add(a, b)).toBe(a + b)`、手工按同样方式导出的快照、把常量断言为它自己），于是它按构造必然通过，永远不可能与代码不一致。期望值必须来自独立的事实源：已知正确的手写字面量、算过的例子、spec。
- **水平切片**：先写完所有测试，再写所有实现。批量测试验证的是*想象中*的行为：你测的是东西的*形状*而不是用户可见行为，测试对真实变化变得不敏感，而且你在理解实现之前就锁定了测试结构。改为**垂直切片**：一个测试 → 一个实现 → 重复，每个测试都是一颗 **tracer bullet**，回应上一轮循环教给你的东西。

## 循环的规则

- **红先于绿。** 先写失败的测试，然后只写足够让它通过的代码。不要预判后续测试，不要加投机性的功能。
- **一次一个切片。** 每个循环一个接缝、一个测试、一个最小实现。
- **重构不属于这个循环。** 它属于评审阶段（见 `code-review` 技能），不属于红 → 绿的实现循环。
